# v0.1.2 — 打招呼顺便记一条日志

## 需求

打完招呼想顺便记一条日志，但不想让 `app()` / greeter 认识"记日志"这件事——以后还可能加统计、加告警，不能让打招呼的代码知道有多少个东西在关心它。

## 代码

在 `vanilla/index.ts` 基础上加一个手写的监听器数组：

```ts
type GreetListener = (name: string) => void
const greetListeners: GreetListener[] = []

function onGreet(fn: GreetListener) {
  greetListeners.push(fn)
}

function offGreet(fn: GreetListener) {
  const i = greetListeners.indexOf(fn)
  if (i >= 0) greetListeners.splice(i, 1)
}

function emitGreet(name: string) {
  for (const fn of greetListeners) fn(name)
}
```

`app()` 打完招呼后 `emitGreet('Alex')`，`logger` 通过 `onGreet(logger)` 订阅，彼此不 import 对方。

## 怎么跑

```bash
npm run demo:vanilla
```

## 结果

```
[App] Hello, Alex!
[App] Hello, Alex!
[LOG] greeted Alex
[App] 你好，Alex！
[LOG] greeted Alex
```

第一次 `app()` 时还没人订阅，`emitGreet` 空转，没有 `[LOG]`。订阅之后每次打招呼都会触发日志，换语言（英文→中文）不影响日志——两件事已经解耦。

## 这一步暴露的问题

`offGreet` 写出来了，但**没有任何东西强制调用它**。这段代码里没人退订，所以看不出问题；但设想一个长期运行的系统，`logger` 这种订阅者如果在某个时刻该被换掉或移除，谁负责调用 `offGreet(logger)`？忘记调用不会报错，只会在监听器数组里留下一个永远不会再被清理的幽灵函数。这个风险不是这一步引入的 bug，而是这种手写方式**结构性地**依赖"记得手动清理"这件事。
