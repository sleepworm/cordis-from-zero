# v0.1.4 — 道别语也要跟着"现在几点"变

## 需求

加一个新能力 `Farewell`（道别语），和 `Greeter` 一样依赖 `Clock`，但和 `Greeter` 没有任何关系——不共享代码，互不知道对方存在。这是全篇第一次出现"不止一个模块依赖同一个东西"。

## 代码

`Farewell` 的实现和 `Greeter` 结构完全对称：

```ts
let farewell: Farewell | undefined

function refreshFarewell() {
  farewell = clock ? makeFarewell(clock) : undefined
}
```

对照 v0.1.3 的 `refreshGreeter`，这两个函数**逐行一样**，只是换了个名字。真正暴露问题的不是这四行本身，而是所有触碰 `clock` 生命周期的地方，现在都要同时改两处：

```ts
loadClock()
refreshGreeter()  // clock 一变化，两个依赖方都要手动刷新——
refreshFarewell() // 这一行是上一步 refreshGreeter() 的原样复制，只是换了个名字
```

`unloadClock()` 之后同样要刷新两次。

## 怎么跑

```bash
npm run demo:vanilla
```

## 结果

```
[App] greeter unavailable, skip greeting
[App] farewell unavailable, skip farewell
[App] Good morning, Alex!
[LOG] greeted Alex
[App] Have a great day, Alex!
[App] 早上好，Alex！
[LOG] greeted Alex
[App] greeter unavailable, skip greeting
[App] farewell unavailable, skip farewell
[App] 晚上好，Alex！
[LOG] greeted Alex
[App] Good night, Alex!
```

`greeter` 和 `farewell` 在 clock 缺失/恢复时**同步**变得不可用/恢复可用——但这个"同步"不是自动发生的，是因为每个调用点都手动把两个 `refresh` 函数并排写在了一起。

## 这一步暴露的问题，也是 vanilla 这条线的收尾论点

从 v0.1.1 到现在，`vanilla/index.ts` 里真正和"打招呼/道别"这件事相关的代码没怎么变过；变多的全是**依赖管理的胶水代码**：一个 `ready` 变量、一个 `refresh` 函数、以及所有调用点上要记得成对调用的同步逻辑。这一步把胶水代码复制了一份，如果再加第三个依赖 `clock` 的模块，还得再复制一份——**每多一个依赖方，胶水代码就线性增加一份，且没有任何地方能把这份重复消掉**（除非自己再发明一层抽象，但那基本就是在手写一个简化版的依赖注入框架）。

这正是 vanilla 这条线要留给 Cordis 线回答的问题：同样的四个需求，如果用 Cordis 写，这些胶水代码会变成什么样？
