# v0.2.4 — 同 v0.1.4，改用 Cordis

## 需求

和 `v0.1.4` 完全一样：加一个新能力 `Farewell`，和 `Greeter` 一样依赖 `Clock`，但和 `Greeter` 没有任何关系。

## 代码

`Farewell` 和 `Greeter` 结构完全对称，同样只需要一行依赖声明：

```ts
abstract class Farewell extends Service {
  static inject = ['clock']
  constructor(ctx: Context) {
    super(ctx, 'farewell')
  }
  abstract farewell(name: string): string
}
```

`Farewell` 和 `Greeter` 之间**没有任何 import 关系，互不知道对方存在**。装载也只是多一行：

```ts
let greeterFiber = await ctx.plugin(EnglishGreeter)
await ctx.plugin(EnglishFarewell) // 除了 static inject = ['clock']，不需要任何额外胶水代码
```

## 怎么跑

```bash
npm run demo:cordis
```

## 结果

```
[App] ctx.greeter is unavailable, skip greeting
[App] ctx.farewell is unavailable, skip farewell
[App] Good morning, Alex!
[LOG] greeted Alex
[App] Have a great day, Alex!
[App] 早上好，Alex！
[LOG] greeted Alex
[App] ctx.greeter is unavailable, skip greeting
[App] ctx.farewell is unavailable, skip farewell
[App] 晚上好，Alex！
[LOG] greeted Alex
[App] Good night, Alex!
```

和 `v0.1.4` 的现象逐条一致：`Clock` 缺失/恢复时，`greeter` 和 `farewell` **同步**变得不可用/恢复可用；卸载 `Greeter` 不影响 `Farewell`（本章没有单独重复这个动作，但可以自己在 `main()` 里加一段验证——`Farewell` 的存在完全不依赖 `Greeter`）。

## 对照 v0.1.4：全篇的边际成本论点

`v0.1.4` 里 `refreshFarewell()` 是 `refreshGreeter()` 的逐行复制，而且**所有触碰 `clock` 生命周期的调用点都要同时改两处**——这是那一章暴露的问题：每多一个依赖方，胶水代码线性增加。

这里的对照是全篇最关键的一组数字：

| | Cordis 版 | Vanilla 版 |
|---|---|---|
| `Greeter` 声明依赖 `clock` | `static inject = ['clock']`（1 行） | `refreshGreeter`/`loadGreeter`/`unloadGreeter` + 2 个状态变量（约 18 行） |
| 再给 `Farewell` 声明同样的依赖（边际成本） | 再加一行 `static inject = ['clock']` | 把上面 18 行原样复制一份，改个名字（约 20 行） |
| `Clock` 本身要不要跟着改 | 不用，`RegistryService` 天然支持任意多依赖方 | 不用，前提是 `clock.ts` 一开始就用了 `Set<Waiter>` 而不是单个回调 |
| 装载新依赖方时，调用点要不要改 | 不用，`ctx.plugin(EnglishFarewell)` 之后框架全包了 | 要，每个碰 `clock` 生命周期的地方都要多写一行 `refreshFarewell()` |

**结论**：Cordis 每新增一个依赖方，边际成本是**常数**（1 行声明）；Vanilla 每新增一个依赖方，边际成本是**复制一整套状态机模板**（约 20 行），而且这套代码没有天然可以复用的地方——继续加第三个、第四个依赖 `Clock` 的模块，Vanilla 这边会持续线性累积几乎相同的样板代码，Cordis 那边始终只是多一行 `static inject`。

这是 `v0.1.x`/`v0.2.x` 两条线从 `v0.1.1` 一路铺到这里要证明的东西：**HelloCordis 规模小的时候看不出优势，优势要等到"多个依赖方共享同一个能力"这种情况出现才会显现，而且是随依赖方数量线性放大的。**
