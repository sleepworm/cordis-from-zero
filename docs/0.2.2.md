# v0.2.2 — 同 v0.1.2，改用 Cordis

## 需求

和 `v0.1.2` 完全一样：打完招呼顺便记一条日志，且不想让 `app()`/`Greeter` 认识"记日志"这件事。

## 代码

`Events` 接口扩展给 `ctx.emit`/`ctx.on` 加上类型约束（和 `Context` 接口扩展是同一套机制）：

```ts
declare module 'cordis' {
  interface Context {
    greeter: Greeter
  }
  interface Events {
    greet(name: string): void
  }
}
```

`app()` 打完招呼后 `ctx.emit('greet', 'Alex')`；`logger` 是一个普通的函数式 Plugin，只是它做的事情是订阅事件，而不是 provide 一个 Service：

```ts
function app(ctx: Context) {
  console.log('[App]', ctx.greeter.greet('Alex'))
  ctx.emit('greet', 'Alex')
}

function logger(ctx: Context) {
  ctx.on('greet', (name) => {
    console.log(`[LOG] greeted ${name}`)
  })
}
```

装载和 `Greeter` 一样，走 `ctx.plugin()`：

```ts
await ctx.plugin(logger)
```

## 怎么跑

```bash
npm run demo:cordis
```

## 结果

```
[App] Hello, Alex!
[App] Hello, Alex!
[LOG] greeted Alex
[App] 你好，Alex！
[LOG] greeted Alex
```

和 `v0.1.2` 的输出逐字一致。

## 对照 v0.1.2

`v0.1.2` 里手写了三个函数（`onGreet`/`offGreet`/`emitGreet`）和一个数组，`offGreet` 写出来了但没人调用——这是那一章暴露的问题。这里 `ctx.on()` 内部就是 Cordis 的 `effect` 机制：订阅动作本身会被记录在当前这个 Plugin 的生命周期里，`logger` 这个 Plugin 被卸载时，它注册的所有 `ctx.on()` 监听会**自动**被撤销，不需要手写、也不需要记得调用任何等价于 `offGreet` 的东西。

`v0.1.2` 的胶水代码（监听器数组 + 三个函数）在这里完全消失了，`logger` 里只剩下一行 `ctx.on('greet', ...)`——这是全篇第一次出现"代码变短、且少了一类真实风险"的对照。
