# v0.1.3 — 问候语要跟着"现在几点"变

## 需求

问候语要跟着时段变（早上/下午/晚上说不同的话），而"现在几点"这件事本身也可能还没准备好——模拟一个真实系统里"某个依赖可能暂时不可用"的场景，不读真实系统时间，用一个可以手动装卸的 `Clock` 代替。

## 代码

`Clock` 很简单，`load`/`unload` 就是给一个模块级变量赋值/清空：

```ts
let clock: Clock | undefined

function loadClock(period: Period = 'morning') {
  clock = { period }
}

function unloadClock() {
  clock = undefined
}
```

问题出在 `greeter` 身上：`greeter` 存不存在，现在**依赖** `clock` 存不存在，但 `clock` 自己完全不知道 `greeter` 的存在。于是需要一个"同步"函数，而且**没有任何机制会自动调用它**——每次 `clock` 变化后，得自己记得手动调一次：

```ts
let greeter: Greeter | undefined

function refreshGreeter() {
  greeter = clock ? (useEnglish ? makeEnglishGreeter(clock) : makeChineseGreeter(clock)) : undefined
}

loadClock()
refreshGreeter()   // 忘了这一行，greeter 就不会知道 clock 已经来了
```

`app()` 还是只检查 `greeter` 这一个变量（和 v0.1.1/v0.1.2 的写法一致），但 `greeter` 是否可用，现在悄悄地系在了"有没有人记得调用 `refreshGreeter()`"这件事上。

## 怎么跑

```bash
npm run demo:vanilla
```

## 结果

```
[App] greeter unavailable, skip greeting
[App] Good morning, Alex!
[LOG] greeted Alex
[App] 早上好，Alex！
[LOG] greeted Alex
[App] greeter unavailable, skip greeting
[App] 晚上好，Alex！
[LOG] greeted Alex
```

clock 未加载时 greeter 不可用；`loadClock()` + `refreshGreeter()` 之后可用，问候语带上时段；换语言不受影响；`unloadClock()` 之后又变回不可用；重新 `loadClock('evening')` 之后恢复，且文案跟着新时段变。

## 这一步暴露的问题

和 v0.1.2 的 `offGreet` 一样的形状：`refreshGreeter()` 是个必须记得调用、但没有任何东西强制调用的函数。区别在于——v0.1.2 只要忘一次，最多是内存里多个不会触发的监听器；这里忘一次，`greeter` 会**悄悄停留在过期状态**（比如 clock 已经卸载了，greeter 却还在用旧的 clock 引用），是一个更隐蔽、更容易在真实系统里造成"看起来没报错，但答案是错的"的 bug。这条"手动同步"的胶水代码，会在下一步（第二个依赖 clock 的模块）里被逼着复制一份。
